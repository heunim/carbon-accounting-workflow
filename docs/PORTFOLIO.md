# 求职展示材料

## 项目定位

面向双碳和ESG岗位，展示把核算方法落到数据结构、代码、复核流程和报告中的能力。软件原型可以作为个人作品，虚构案例不能描述为真实客户或企业项目。

## 简历表述

CarbonFlow企业碳核算工作流｜个人项目

- 设计并实现基于Python与Streamlit的企业碳核算原型，支持活动数据导入、范围1/2/3归类、因子匹配、单位及CO₂e转换、热点分析和结果导出。
- 整理52条带来源及适用条件的精选因子，将归类规则、因子和GWP参数外置至Excel，并设计缺数据、缺因子、国外代理与人工确认的处理流程。
- 实现逐行计算追溯、结构化审计日志和可选AI建议模块，使用候选ID白名单及人工确认约束AI输出，避免生成无来源因子或直接参与计算。

以上文字描述当前功能。应结合实际参与程度调整措辞，准备解释自己负责的需求、核算方法、数据审查和代码验证。不填写未经测试的节省工时、准确率、减排量或企业应用数量。

## 三分钟演示

第一分钟，展示结果与依据。

打开默认虚构案例，说明12条活动中9条已计算，3条待处理。展示16.351 tCO₂e已计算小计、范围构成和Top3热点。强调这不是完整企业排放总量。打开天然气或电力记录，展示因子来源、活动单位和计算公式。

第二分钟，处理一个实际数据问题。

切换活动与人工确认，选择用途未知的柴油记录。将用途设为移动，填写演示密度0.84 kg/L，并注明这是虚构案例参数。确认缺省热值适用后保存。该条计算为50 × 0.84 ÷ 1000 × 3186.3 = 133.8246 kgCO₂e。观察待处理条数减少，但高铁仍因缺少适用因子而保留。

第三分钟，展示审计与AI边界。

下载结果Excel，展示待处理清单、因子快照及GWP快照。打开审计记录，说明哪些输入和确认使结果发生变化。AI配置完成后可以建议候选，但不计算、不生成因子，且用户确认后仍要通过确定性检查。没有Key时演示人工确认即可，不把未运行的真实API描述为已验证。

## 面试可回答的问题

1. 为什么CO₂和CO₂e要分开？CO₂的GWP为1，已有CO₂e不应重复乘GWP，且单位统一不代表气体覆盖完整。
2. 为什么默认位置法？输入更少，依据明确。购电情景另外展示，没有证据不包装成实际市场法结果。
3. 因子库不完整怎么办？报告已计算小计和具体缺口，让用户补充有来源的因子，不凭空填0。
4. AI起什么作用？辅助理解模糊描述和解释候选，不代替核算规则或数值计算。
5. 你如何保证能复算？保留输入行号、规则ID、因子ID、来源、版本摘要、单位换算、GWP和人工确认记录。
